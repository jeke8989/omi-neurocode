# Журнал проекта Mnemo

Что изменено, зачем и как откатить. Новые записи — сверху.

## 2026-10-31 — Claude в чате, автообновление сервера, срок хранения звука

**Claude в чате** (ветка `feat/claude-agent`)
- Что: в чате два режима на Claude Code CLI (новый контейнер `claude`, `server/claude/`). «Claude» — ассистент
  Mnemo на подписке владельца: данные через MCP-инструменты gateway (`POST /mcp`, `neuro/mnemo_mcp.py`, одноразовый
  токен на запуск), из встроенных инструментов CLI только WebSearch/WebFetch, кода не видит. «Claude · код» — работа
  в рабочей копии репозитория с пушем. Шаги CLI показываются в чате так же, как шаги агента Mnemo. Токен из
  `claude setup-token` вводится в Настройки → Claude Code и хранится в `settings` (`claude.token`),
  наружу отдаётся только хвост. Сессия CLI продолжается между сообщениями, очистка чата начинает новую.
  Новые эндпоинты: `GET/POST/DELETE /api/claude`, `/health/full` (api, db, claude).
- Зачем: менять Mnemo и выкатывать обновления прямо из чата на телефоне.
- Безопасность: в контейнере `claude` нет `.env`, ключей OpenRouter и базы; push — своим deploy-ключом
  только в этот репозиторий; CLI работает не от root, `mem_limit: 2g`.
- Откат: `git revert` коммита; на сервере `docker compose up -d --remove-orphans`, тома `claude-home`,
  `claude-work` можно удалить (`docker volume rm neurosoft_claude-home neurosoft_claude-work`).

**Автообновление сервера из CI**
- Что: задача `deploy` в `.github/workflows/server.yml` после тестов и e2e по SSH запускает
  `server/ci-update.sh`: пересобирает по одному только сервисы, чьи файлы изменились, проверяет место на
  диске (не хватает — стоп, а не полный диск), ждёт, пока Claude допишет ответ, перезапускает, проверяет `/health`.
  Сервер: 92.112.180.217 (`/opt/mnemo`, порт 8090). Сначала стоял рядом с Jarvis (89.124.114.123, диск 10 ГБ) —
  перенесён, установка там удалена.
  Ключ CI на сервере ограничен `command=`. Добавлен `autoheal` — профиль compose (`COMPOSE_PROFILES=autoheal`
  в `.env`); на сервере рядом с Jarvis выключен, там уже работает свой autoheal с той же меткой.
- Откат: удалить переменную `DEPLOY_HOST` в настройках репозитория (задача пропускается) или строку ключа
  из `/root/.ssh/authorized_keys`.

**Срок хранения звука** (ветка `feat/audio-retention`)
- Что: Настройки → Данные → Звук записей: 1/3/7/30 дней или «Удалять после расшифровки»
  (`settings.audio.keep_days`, модуль `neuro/retention.py`). STT стирает звук сразу после расшифровки,
  уборка агента — каждые 10 минут по выбранному сроку. По умолчанию — `KEEP_AUDIO_DAYS`.
- Зачем: не держать сырой звук на сервере дольше нужного.
- Откат: `git revert` коммита; удалённый звук не восстанавливается, расшифровки не затронуты.
